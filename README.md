## About the work I do

I work at the intersection of **business operations, analysis, automation, and software delivery**. My strength is translating an ambiguous business need into a clear process, a measurable KPI, a useful dashboard, or a working web experience.

My background includes client research, prospecting, outreach, CRM and lead tracking, stakeholder communication, project coordination, vendor coordination, event operations, process improvement, digital strategy, analytics, and responsive web development. I am also a co-founder of **ENVEI**, a workforce-measurement platform focused on understanding how skills, education, and labour-market needs align.

I am building toward roles where I can contribute as a **business analyst, business systems analyst, operations analyst, automation specialist, product operations associate, data analyst, or junior software engineer**.

## My build philosophy

> Start with the business question. Define the process. Make the data trustworthy. Build the smallest useful product. Measure the result. Document the trade-offs.

The projects below are organized as connected build programs rather than unrelated tutorial repositories. Each program contains a problem definition, requirements, data model, automation or implementation layer, dashboard or interface, tests, documentation, and a case study.

## 04 · TrustDesk — Responsible AI Knowledge Assistant

**TrustDesk** is a citation-grounded knowledge assistant for business policies and operations documents. Unlike a generic chatbot, the project is designed to show retrieval quality, source citations, evaluation, privacy boundaries, and refusal behavior.

| Repository / stage | What it demonstrates | Track | Status |
| --- | --- | --- | --- |
| `trustdesk-corpus` | Versioned synthetic documents and metadata | Data foundation | 🗺️ Planned |
| `trustdesk-retrieval` | Keyword and semantic retrieval comparison | AI application | 🗺️ Planned |
| `trustdesk-evaluation` | Retrieval hit rate, citation coverage, groundedness, and refusal tests | AI evaluation | 🗺️ Planned |
| `trustdesk-guardrails` | Input limits, PII-aware handling, and prompt-injection test cases | Responsible AI | 🗺️ Planned |
| `trustdesk-web` | Source-inspection interface with feedback controls | Product UX | 🗺️ Planned |

**Business question:** How can teams get useful answers from internal knowledge without losing the ability to inspect the evidence behind each answer?
